# D2C · DEOCORE TO CLIENT

Раздел CRM: `/outreach`. API: `/api/v1/outreach/`.

## Первый запуск

1. Владелец или администратор открывает «Продажи → D2C · Обзвон → Команда».
2. Назначает руководителя с существующей ролью владельца, администратора или менеджера проекта (для доступа к лидам).
3. Добавляет сотрудников в состав отдела. Участие в D2C не меняет остальные права сотрудника. Клиентов добавлять нельзя.
4. Во вкладке «Импорт D2C» копирует инструкцию для ИИ, вставляет подборку, проверяет предпросмотр и добавляет контакты.

## Правила работы

- Норма по умолчанию 25. Менеджер меняет её в диапазоне 20–40; руководитель — 1–40. Уже выданные сегодня контакты не отзываются при снижении нормы; новая норма ограничивает дальнейшую выдачу и следующий день.
- Выдача происходит автоматически при открытии/обновлении очереди (в открытой вкладке раз в минуту), пн–пт, 09:00 ≤ время < 19:00 по `Asia/Bishkek`. Фоновый планировщик не требуется.
- Сначала в норму включаются необработанные контакты и наступившие повторные попытки, затем резерв распределяется между активными сотрудниками с наименьшим числом выданных за день контактов. Завершение звонка не освобождает дневное место.
- Излишек старых контактов остаётся закреплённым за сотрудником до следующей выдачи. Перезвоны на сегодня и просроченные показаны первыми, сверх нормы; будущие доступны в «Все контакты и история».
- «Не ответил» назначает повтор на следующий рабочий день в 09:00. После трёх таких результатов — «3 попытки без ответа», без дальнейшей автоматической выдачи.
- Для «Перезвонить», «Отказ» и «Заинтересован» обязательна запись. Для «Не ответил» и «Неверный номер» необязательна.
- Перезвон назначается только на будущее рабочее время Бишкека. Оформление результатов и загрузка доступны вне рабочих часов.
- «Заинтересован» атомарно создаёт лид с одноимённым этапом, источником «Звонок», данными D2C и ответственным руководителем. Повтор того же запроса не создаёт второй звонок/лид.
- Менеджер видит только свои контакты и их записи. Руководитель видит весь отдел, импортирует контакты, меняет нормы и перераспределяет активные контакты. При паузе новые контакты не выдаются; существующие руководитель перераспределяет вручную.

## Формат D2C

```text
Компания: Название компании
Телефон: +996700123456
Сфера: Мебель на заказ
Предложение: CRM для контроля заявок и замеров
УТП: Все заказы и договорённости в одной карточке
Начало разговора: Добрый день! Как вы сейчас ведёте заявки?
Возражения: Уже есть таблица — предложим сравнить время контроля заказов.
---
Компания: Следующая компания
Телефон: +996700123457
Предложение: Разработка сайта
```

Обязательны компания, телефон с кодом страны, предложение. Остальные поля поддерживают несколько строк. До 500 компаний / 1 МБ текста за один импорт. Телефоны нормализуются, повторы внутри подборки и ранее импортированные номера пропускаются. Ошибка формата отменяет весь импорт. Поддерживается также JSON-массив с полями `company`, `phone`, `industry`, `offer`, `usp`, `script`, `objections`.

## Записи и эксплуатация

До 30 МиБ на файл: MP3, M4A, WAV, OGG, AAC, WEBM, AMR, 3GP. Воспроизведение зависит от поддержки формата браузером; доступно скачивание. Файлы передаются частями по 1 МиБ и хранятся в БД, как существующие приватные вложения сайта. Публичных ссылок нет; чтение каждой части требует авторизации и доступа к контакту. При росте объёма звонков учитывать размер БД и резервных копий; вынесение в приватное объектное хранилище — отдельное развитие.

Неприкреплённые загрузки старше семи дней можно очищать командой:

```sh
python manage.py cleanup_outreach_uploads
```

Прикреплённые записи эта команда не удаляет. Файлы прикреплённого звонка нельзя перезаписать.

## Релиз и проверка

Новая миграция `outreach/0001_initial.py` только добавляет таблицы. Сначала применить миграцию и выпустить backend, затем frontend. Текущая Vercel-сборка backend уже запускает `manage.py migrate` через `pyproject.toml`.

```sh
cd backend
python manage.py migrate --noinput --settings=config.settings.production
pytest apps/outreach apps/leads --ds=config.settings.test -q
cd ../frontend
npm test -- --runInBand src/views/outreach/OutreachPage.test.tsx
npm run typecheck
npm run build
```

Не включать в релиз посторонние незакоммиченные изменения авторизации, финансов, проектов и задач из рабочего каталога. Проверить целевые проекты backend/frontend перед выкладкой. После публикации проверить вход, настройки отдела, импорт-предпросмотр и передачу тестового контакта руководителю; тестовые данные не создавать среди реальных клиентов без отдельной договорённости.
