# DEO STUDIO CRM — мобильное приложение

Нативный клиент Flutter для Android и iOS. Приложение использует общие данные веб-CRM.

## Подключение

По умолчанию сборки обращаются к production:

- REST: `https://crm.backend.deo-core.codes/api/v1`
- WebSocket: `wss://crm.backend.deo-core.codes`

Адреса можно заменить при сборке:

```sh
flutter run --dart-define=API_BASE_URL=https://crm.backend.deo-core.codes/api/v1 --dart-define=WS_URL=wss://crm.backend.deo-core.codes
```

Для локальной разработки на физическом телефоне используйте доступный ему адрес сервера, а не localhost.

## Реализованные сценарии

- Вход, получение профиля, восстановление сессии и обновление токенов; вход с TOTP или резервным кодом.
- Нативные списки, поиск, постраничная загрузка, карточки, создание и редактирование клиентов, проектов, задач, лидов, сделок, каталога и других доступных серверных ресурсов.
- Серверные формы OPTIONS: поля, обязательность, варианты, вложенные позиции счетов/сделок/пакетов, выбор связанных записей со всех страниц справочника. Запросы серверу определяют права доступа; серверная проверка остаётся окончательной.
- Календарь сроков задач и проектов, тепловая карта нагрузки сотрудников.
- Доски лидов и задач, изменение этапов и статусов, назначение исполнителя, подзадачи, таймеры и комментарии.
- Финансовые операции, оплата счетов и сделок, пополнение каталога, импорт/экспорт CSV, массовое изменение статусов, категорий и цен.
- Документы, загрузка файлов, версии, комментарии и открытие ссылок скачивания.
- Чаты: создание, отправка и получение сообщений, участники, вложения по ссылкам, переподключение WebSocket и периодическое обновление по REST.
- Входящие Telegram/WhatsApp, действия с диалогами, отправка сообщений через серверные формы; настройка интеграций.
- A/B-тестирование: генерация вариантов предложений, отметки отправки/просмотра/конверсии и история конверсий.
- AI: ввод данных, реальная генерация, показ результата и история; настройка провайдера.
- Клиентский кабинет, сотрудники, структура студии, наставничество, обучение, формы, автоматизация, напоминания, уведомления и бизнес-аналитика доступны через «Ещё → Все разделы CRM».
- Редактирование профиля, смена пароля, настройка двухфакторной защиты и сохранение предпочтений уведомлений.

Формы используют действующий контракт сервера; при отсутствии разрешений или маршрута приложение показывает серверную ошибку. Мобильные экраны остаются нативными и не повторяют веб-вёрстку. Полное равенство всех специализированных веб-сценариев ещё требует отдельной проверки: расширенные шаблоны, все типы автоматизации и действия со вложенными коллекциями для каждой роли.

## Проверка и сборка

```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
flutter build ios --simulator
```

Тесты проверяют реальный формат серверных сериализаторов, вход с ответом из одних токенов, 2FA, серверные формы, обязательные поля, карточки и безопасную пагинацию. Они используют локальные ответы API и не изменяют production-данные. Проверка под реальной учётной записью отдельно обязательна перед выпуском.

Android debug-сборка предназначена для проверки. Для выпуска нужна собственная подпись; iOS также требует настройку Apple signing. Текущий Flutter поднимает минимальную версию iOS до 15.

Офлайн-доступ ограничен чтением ранее полученных данных в старых нативных API-экранах. Изменения требуют соединения. Кеш разделён по пользователям и очищается при входе, выходе и изменениях.

Приложение `../deo_atc` и серверный модуль телефонии не изменялись.
